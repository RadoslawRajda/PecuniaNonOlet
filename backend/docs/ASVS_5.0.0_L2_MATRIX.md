# OWASP ASVS 5.0.0 — macierz L2 (backend)

Źródłem identyfikatorów jest przypięty plik [CSV OWASP ASVS 5.0.0](ASVS_5.0.0_SOURCE.csv), pobrany z oficjalnego [CSV OWASP ASVS 5.0.0](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/docs_en/OWASP_Application_Security_Verification_Standard_5.0.0_en.csv) (blob `184cf3b04a8fe1809dbed8b6e73be7a6fbaf8689`, SHA-256 `98c8fe911b9edb403af8ee05d3ce8201ecac2659e313b053890a62847cdcf680`). Zakres Level 2 obejmuje 70 wymagań L1 i 183 wymagania L2 (łącznie 253). Lista poniżej jest checklistą do oceny tego backendu; sama obecność identyfikatora nie oznacza zgodności.

## Zasady oceny

- **Potwierdzone** — istnieje dowód w kodzie i aktualny, uruchomiony test lub niezależna weryfikacja.
- **Częściowo** — mechanizm istnieje, ale brakuje części pokrycia albo weryfikacji.
- **Brak** — wymaganie nie jest spełnione.
- **N/D** — wymaganie nie ma zastosowania do aktualnej architektury; uzasadnienie jest obowiązkowe.
- **Nieocenione** — nie ma wystarczającego dowodu. Nie jest to status zaliczenia.

Wykaz poniżej obejmuje wszystkie 253 wymagania L1+L2 ze źródłowego CSV. Każdy wiersz zawiera oryginalne brzmienie wymogu, status, ścieżkę dowodową i ograniczenie. Status „Częściowo”, „Brak” lub „Nieocenione” nie jest zaliczeniem. N/D stosuje się tylko tam, gdzie funkcji faktycznie nie ma; ograniczenia aplikacji mobilnej lub środowiska wdrożeniowego pozostają jawnie poza zakresem audytu backendu.

## Wyniki testów dla backendu

- Commit `269b0e3`: `pytest` 222 passed na Pythonie 3.11.0, 3.12.2 i 3.13.7; Ruff lint, Ruff format i mypy zaliczone na Pythonie 3.12.2. Klient: Jest 28 passed oraz `tsc --noEmit` zaliczone po zmianie Google `/reauth`.
- Historyczny baseline na SHA review: Python 3.11, 3.12 i 3.13 — 188 passed oraz Ruff/mypy. Nie jest to wynik bieżącego drzewa.
- Pełny `pip-audit -r requirements.lock.txt` na niezmienionym lockfile zakończył się wynikiem `No known vulnerabilities found` (z lokalnym `--cache-dir`; bez `--no-deps`). Wynik zależy od stanu bazy podatności w dniu wykonania.
- Zakres nie obejmuje iOS/Android end-to-end, rzeczywistych zewnętrznych Google/Cloudflare/NBP, produkcyjnej konfiguracji TLS ani operacyjnego monitoringu.

Weryfikacje krytyczne wraz z dowodami są opisane w [przeglądzie bezpieczeństwa](SECURITY_REVIEW.md). Pozycje nadal oznaczone jako „Nieocenione” pozostają otwarte i nie są zaliczone.
